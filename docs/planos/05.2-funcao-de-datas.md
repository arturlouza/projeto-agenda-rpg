# Plano da etapa 5.2: função auxiliar de datas

## Contexto

O app segue o horário de Brasília (seção 6.4), mas as datas são gravadas em UTC. Quase tudo que vem depois (data nova, atraso, listagens) precisa responder "que dia é em Brasília?". Esta etapa cria esse ponto único, ainda sem rota nem mudança no `/docs`.

Conferi no `.venv`: o `tzdata` não está instalado, e a versão `2026.6` existe no PyPI. O Windows não traz a base de fusos, por isso o `ZoneInfo` precisa desse pacote.

## O que muda

Caminhos relativos à raiz do projeto. Todas as edições ficam comigo.

### 1. `backend/requirements.txt`

Acrescenta a linha `tzdata==2026.6`. A dependência já está autorizada pela especificação.

### 2. `backend/app/dates.py` (novo)

```python
from datetime import date, datetime, timezone
from zoneinfo import ZoneInfo

from app.models import utc_now

# Fuso usado em todo cálculo de "que dia é" (seção 6.4 da especificação).
APP_TIMEZONE = "America/Sao_Paulo"


# Descobre em que dia de Brasília caiu uma data e hora. Sem fuso, ela é tratada como UTC.
def to_app_date(moment: datetime) -> date:
    if moment.tzinfo is None:
        moment = moment.replace(tzinfo=timezone.utc)

    return moment.astimezone(ZoneInfo(APP_TIMEZONE)).date()


# Devolve o dia de hoje em Brasília.
def app_today() -> date:
    return to_app_date(utc_now())
```

Decisões:

- **Reaproveito `utc_now` de `models.py`**, em vez de repetir `datetime.now(timezone.utc)`. O `models.py` não importa `dates.py`, então não há import circular.
- **`app_today()` não recebe parâmetro.** Para fixar a hora, o teste troca `app.dates.utc_now` com `monkeypatch`, como a etapa 5.4 prevê e como `test_database.py` já faz com o `engine`.
- **Início e fim do dia e segunda-feira da semana ficam de fora**, porque são das etapas 5.5 e 5.6.

## Conceitos que explico depois da alteração

- Data e hora com fuso e sem fuso, e a diferença entre `replace` e `astimezone`.
- O que é o `tzdata` e por que o Windows precisa dele.
- Como o `monkeypatch` fixa a hora, e por que a troca é feita em `app.dates.utc_now`.

## Como verificar

Depois de editar, instalo o `tzdata` no `.venv` e rodo a suíte completa para confirmar o resultado. Depois você confere, na pasta `backend`, com o ambiente virtual ativado:

```powershell

pytest tests/test_dates.py
pytest
python -c "from app.dates import app_today; print(app_today())"
```
